# PDF 原版双语对照

## 解决的问题

旧实现将 PDF 转换成连续文本，再翻译成 Markdown。这个流程丢失原页坐标和栏位，不能通过调整 CSS 恢复原版。新默认阅读器使用同一张原始 PDF 页面作为左右背景，右侧按区域覆盖对应译文；旧文本精读作为辅助模式保留。

## 实现

- PDF.js 在 viewport 坐标系中取得文本项，保留位置、字号、宽高；邻近片段按视觉行合并，跨栏间隙分开处理。纵向相邻、字号相近的行合并为段落区域。
- 排版版本 2 在视觉行聚合时忽略行内链接颜色和字体切换；按栏位、首行缩进、行距和段尾特征重建自然段，识别列表及续行。正文统一深灰、标题统一深蓝，使用段落行距和悬挂缩进，避免将彩色链接误判为单独段落。译文显式顶端对齐；所有原文遮盖层先于译文绘制。
- 原页 Canvas 完整保留图像、表格线、公式和页眉页脚。右侧仅遮盖已完成翻译的文字行，回填对应中文；附近像素用于估计底色与字色。
- 译文请求启用 JSON 输出，每批最多 6 个区域、约 2200 字符，并限制输出预算。按精确区域 ID 校验，完整返回的区域立即保存，漏回的区域自动切换单段补译。截断 JSON 只恢复已经闭合的完整字符串；不根据顺序猜测对应关系。网络、密钥或额度错误停止请求，保留已完成内容，下一次仅处理缺失区域。
- 字号与行距按区域高度适配；长译文达到最小字号后仍放不下时，标出橙色边框，并允许打开完整译文编辑，避免把裁切视为翻译完成。
- 左右共用页面尺寸和缩放比例，横纵滚动位置同步。原文选区高亮以页面坐标保存，缩放后继续定位；译文编辑在原位重新适配。
- IndexedDB 存储 `layoutTranslations` 与 `pdfHighlights`。版本与源区域标识不符时不套用旧结果。旧 Markdown 译文单独保留。
- 旧版区域缓存按原页几何归属迁移到段落。只复用可完整匹配的片段，不将跨段片段猜测性拆分；原缓存保存到 `previous` 作为备份。无法可靠匹配的区域保留待译状态，已有高亮不受段落重建影响。

## 验证

阅读空间支持调整：中线左右拖动改变原文/译文比例（25% 至 75%），底边上下拖动调整高度，也可选择充满可用空间。双击分隔线恢复默认；聚焦分隔线后可用方向键微调。“专注阅读”以网页视口铺开并隐藏外围导航，Esc 或“退出专注”返回。比例、高度和专注状态保存在浏览器，切页后保留。两栏分别适配栏宽，同步滚动按 PDF 坐标换算。

`npm run test:pdf-layout` 检查双栏不串列、表格单元格隔离、数值与公式保留、换行适配及溢出信号。另运行 TypeScript、ESLint 和生产构建。

翻译回归包括 37 区域页面漏 ID、JSON 结构变化、截断响应、空响应、超长区域、密钥/网络失败及取消；浏览器验收故意注入漏 ID 和截断响应，检查自动补译与逐区保存。适合宽度模式按阅读容器扣除实际滚动条、内边距后的宽度计算，避免 Windows 滚动条导致水平溢出。

段落排版回归覆盖双栏内混合颜色/字体、首行缩进、短尾句、独立项目符号、列表续行与旧缓存迁移。浏览器使用含上述特征的真实渲染 PDF 和模拟译文检查正文颜色、顶端对齐、列表缩进、区域不重叠及刷新恢复；另验证旧缓存迁移不请求模型且保留完整备份。

浏览器使用真实双栏 PDF（包含图像、表格和公式）及模拟翻译响应，验证两侧页面渲染、区域回填、原位编辑、高亮、同步滚动缩放、切页取消与刷新恢复。该验收证明版式与交互流程，不代表真实模型翻译质量。

## 适用范围

当前是浏览器中的版式对照视图，不生成可下载的中文 PDF。适用于包含可提取文本层的学术 PDF。复杂背景上的嵌字、跨栏异形文本、旋转文本、复杂数学排版与扫描页面不能保证逐像素还原。公式按规则识别并尽可能保留原图；文字型图注可翻译，纯图片内部文字未执行 OCR。译文过长的区域需人工审阅。

内置旧合成研读样例只有文本数据，没有原始 PDF，因此仍展示文本精读。上传真实 PDF 后默认使用原版对照。
